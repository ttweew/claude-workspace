PR（Pull Request）是什麼？

可以想成每次更新的「申請單」：裡面寫著改了哪些程式、為什麼要改、怎麼測試的、改前改後的比較。合併之後永久保存，任何一次更新都能回頭查，也能退回到任何一個版本。這次報告的 PR #7～#60，就是 54 張這樣的申請單。

很多人會問我們 push 了這麼多次在做什麼。每一次更新都走這五個步驟：先在分支上改，不會影響正式網站；跑完自動化測試；開一個 PR 寫清楚改了什麼、為什麼、測試結果；合併後 GitHub 會自動在一分鐘內更新網站。PR 就像申請單，每一張都保留下來，所以我們的每一個改動都有紀錄可以查。
