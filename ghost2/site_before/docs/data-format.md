# 關鍵點資料格式說明

這份文件說明網站「數據」面板錄製、匯出的資料格式，回答老師的兩個問題：
- **第 5 題**：資料要用什麼格式保存，之後才能交給後端 AI 分析
- **第 6 題**：x、y、z 各代表什麼、怎麼驗證這些數字

## 怎麼錄製

1. 開啟鏡頭，按工具列的「數據」
2. 按「● 開始錄製」做動作，做完按「■ 停止錄製」（最多錄 5 分鐘）
3. 按「下載 CSV」或「下載 JSON」

檔名是錄製開始的時間，例如 `pose_20261001_153012.csv`。

## 兩種格式，用途不同

| 格式 | 給誰用 | 特色 |
|---|---|---|
| CSV | Excel、Google 試算表、Python（pandas） | 一列一格畫面，打開就能畫圖、算平均 |
| JSON | 之後的後端 AI（上傳用） | 多了裝置與設定資訊，程式讀取方便 |

兩種格式的數字完全相同，都是 **MediaPipe 原始輸出**（沒有經過畫面上的平滑處理），分析時才能自己決定要怎麼過濾。

## 座標的意思

每個點有兩組座標。

### 1. 畫面座標：`x`、`y`、`z`、`visibility`

| 欄位 | 意思 | 範圍 |
|---|---|---|
| `x` | 在畫面中的左右位置，0 是最左邊、1 是最右邊 | 通常 0～1；超出代表在畫面外（模型用猜的） |
| `y` | 在畫面中的上下位置，0 是最上面、1 是最下面 | 同上 |
| `z` | 相對深度：以**髖部中心**為 0，**越小（負越多）越靠近鏡頭** | 大約和 x 同一個比例尺 |
| `visibility` | 模型認為這個點真的看得到的機率 | 0～1；網站畫面上低於 0.65 的點不畫 |

- 座標是**鏡頭原始畫面**，沒有鏡像。前鏡頭的畫面在網站上有鏡像，但錄下來的資料沒有。
- 「左、右」是被拍攝者本人的左右，例如 `left_knee` 一定是本人的左膝。
- `z` 是模型從單張畫面推估的，不是真的量出來的距離，所以要做下面的驗證實驗。

### 2. 真實世界座標：`wx`、`wy`、`wz`（單位：公尺）

MediaPipe 另外推估一組以**公尺**為單位的 3D 座標，原點是**髖部中心**：
- `wx`：左右
- `wy`：上下（往下為正）
- `wz`：前後（越小越靠近鏡頭）

這組座標**理論上不受人站多遠影響**（站遠站近，膝蓋到腳踝都大約是同樣的公尺數），適合用來比較**動作幅度**。

> **注意：前後深度（`wz`）的誤差很大。** 我們用一張雙腿伸直、身體與鏡頭平行的照片實測，伸直的腿用畫面座標算是 174°，用公尺座標算卻是 152°。所以網站上顯示的**關節角度是用畫面座標（2D）計算**，並建議從**側面**拍攝深蹲等動作。公尺座標仍完整保存，可以用下面的實驗 D、E 驗證後再決定要不要使用。

## CSV 欄位

| 欄位 | 說明 |
|---|---|
| `frame` | 第幾格（從 0 開始） |
| `time_ms` | 距離開始錄製幾毫秒 |
| `detected` | 這一格有沒有偵測到人（1 有、0 沒有；沒有時座標欄位空白） |
| `nose_x`、`nose_y`、`nose_z`、`nose_vis` … | 33 個點的畫面座標，共 132 欄 |
| `nose_wx`、`nose_wy`、`nose_wz` … | 33 個點的公尺座標，共 99 欄 |

點的名稱和網站上的編號對照表相同（`js/landmarks.js`），例如 `left_knee` 是 25 號。共 234 欄。

## JSON 結構

```json
{
  "format": "ai-sport-pose",
  "version": 1,
  "meta": {
    "app": "AI 智慧運動分析系統",
    "model": "pose_landmarker_lite",
    "computeMode": "GPU",
    "videoWidth": 640,
    "videoHeight": 480,
    "displayMirrored": true,
    "userAgent": "…",
    "startedAt": "2026-10-01T07:30:12.000Z"
  },
  "landmarkNames": ["NOSE", "LEFT_EYE_INNER", "…"],
  "fields": { "landmarks": ["x", "y", "z", "visibility"], "world": ["x", "y", "z"] },
  "frames": [
    { "t": 0,  "landmarks": [[0.512, 0.301, -0.402, 0.999], "…共 33 點"], "world": [[0.01, -0.62, -0.25], "…"] },
    { "t": 50, "landmarks": null, "world": null }
  ]
}
```

- `t`：距離開始錄製幾毫秒；`landmarks` 為 `null` 代表這一格沒偵測到人
- `version`：之後格式如果改變就加 1，後端可以依版本號讀取

## 為什麼這樣設計（給後端 AI 的考量）

1. **只傳關鍵點，不傳影片**：每格約 1.9 KB，一分鐘約 2～3 MB（每秒 20～30 格），同長度的影片通常要數十 MB；也不會把使用者的臉傳出去，隱私比較好
2. **保留原始資料**：平滑、過濾、算角度都在後端做，之後換方法時不用重錄
3. **畫面座標與公尺座標都保留**：畫面座標可以和影片對照、計算角度；公尺座標保留給之後驗證與研究
4. **沒偵測到的格子也記錄**：時間軸才是連續的，看得出中間斷掉多久

## 驗證實驗建議（第 6 題）

用來確認 x、y、z 的數字是否可信。每個實驗都錄一段，下載 CSV 後用 Excel 畫折線圖。

| 實驗 | 怎麼做 | 預期結果 |
|---|---|---|
| A. 靜止穩定度 | 全身入鏡站著不動 10 秒 | 各點的 x、y 幾乎是一條水平線；可算標準差當作「雜訊大小」 |
| B. x、y 方向 | 只把右手慢慢往右平舉，再往上舉 | 右腕的 x、y 隨動作平順地變化，其他點不動 |
| C. z 深度方向 | 側身站，右手往鏡頭方向伸直再收回 | `right_wrist_z` 伸出時變小（負更多）、收回時變大 |
| D. 公尺座標的尺度 | 量自己大腿長度（髖到膝），站遠、站近各錄一次 | `wx/wy/wz` 算出的髖到膝距離接近實際長度，且兩次差不多 |
| E. 鏡頭距離影響 | 同一個深蹲動作，在 2 公尺、3 公尺各做一次 | 畫面座標的幅度會變，公尺座標的幅度應該差不多 |
| F. 裝置差異 | 同一個人、同一個動作，用筆電和手機各錄一次 | 比較 A 的雜訊大小與 `visibility`，找出哪種裝置比較穩 |

實驗 D、E 最重要：如果公尺座標在不同距離下都一致、深度誤差可接受，之後就能改用 3D 計算角度，不再限制只能從側面拍。
