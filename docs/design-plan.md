# 網站版面與導覽重新規劃

目標：讓網站看起來更舒服、操作更直覺。第一次來的人知道從哪裡開始；運動時站在 2～3 公尺外也看得懂畫面；做完運動知道去哪裡看結果。

每完成一個階段，就把狀態改成「完成」並寫上 PR 編號。

## 一、現況盤點（2026-10 截圖檢查）

| 頁面 | 問題 |
|---|---|
| 首頁 | 沒有導覽列：「錄製資料重播分析」只在頁尾一行小字，很難找到 |
| 首頁（手機） | 4 張功能卡片疊成一長串，要滑很久才看到「開始前的準備」；手機上沒有示意圖，畫面缺少視覺重點 |
| 鏡頭畫面 | 工具列只有文字按鈕、沒有圖示；「關閉鏡頭」和其他按鈕長得一樣，不容易一眼找到怎麼結束 |
| 鏡頭畫面（手機直拿） | 提示橫幅、運算標籤擠在上方，大字儀表板在最下方，視線要上下跑 |
| 鏡頭畫面（手機） | 數據面板蓋住大半個畫面 |
| 重播分析 | 只有一個小小的「← 回首頁」，和首頁沒有一致的導覽 |
| 重播分析 | 摘要格子的文字斷行不自然（例如「14.5 秒 · 436」和「格」被拆成兩行） |

## 二、網站架構

```
首頁 ─┬─ 即時分析（開啟鏡頭後的全螢幕畫面）
      ├─ 重播分析（讀錄下來的檔案，看曲線、統計、深蹲每一下）
      └─ 使用說明（新增：拍攝方式、畫面上每個東西的意思、常見問題、隱私）
```

- **導覽列**放在首頁、重播分析、使用說明三頁的最上方，三頁長得一樣。目前在哪一頁會標出來。
- **即時分析**是全螢幕畫面，不放導覽列（運動時不需要，也不能擋住畫面）。它有自己的工具列，「結束」按鈕要最明顯。

## 三、導覽列

| | 手機（窄螢幕） | 電腦（寬螢幕） |
|---|---|---|
| 左邊 | 網站圖示＋簡短名稱 | 網站圖示＋完整名稱 |
| 右邊 | 首頁、重播分析、使用說明（短字、圖示） | 同左，加上「開始分析」主要按鈕 |
| 行為 | 捲動時固定在最上方、背景半透明 | 同左 |

- 只有 3～4 個項目，不用「漢堡選單」（多按一下才看得到），手機上直接全部排出來。
- 目前所在的頁面：綠色底線＋文字變亮。螢幕閱讀器會唸出「目前頁面」（`aria-current="page"`）。
- 每個項目的按鈕高度至少 44 像素，手指好按。

## 四、各頁版面

### 首頁
- 第一個畫面就要看到「開啟鏡頭」。
- 手機上的功能介紹改成 2×2 小格（圖示＋標題＋一句話），不用滑那麼久。
- 「開始前的準備」三個步驟維持，放在功能介紹之前：第一次使用的人最需要的是怎麼擺手機。

### 即時分析（鏡頭畫面）
- 工具列：左邊「✕ 結束」（最明顯）；右邊「編號、數據、全螢幕」改成圖示＋文字。窄螢幕只留圖示，按鈕仍有文字說明給螢幕閱讀器。
- 手機直拿：狀態與提示集中在上方，大字儀表板集中在下方。畫面中間留給人和骨架。
- 數據面板在手機上改成可以收合的下拉面板，預設只露出錄製按鈕與重點數字。

### 重播分析
- 加上和首頁一樣的導覽列。
- 摘要格子的數字不在中間斷行。
- 區塊順序依照使用流程：選檔案 → 摘要 → 角度曲線 → 深蹲分析 → 統計 → 匯出。

### 使用說明（新增）
- 怎麼擺手機（距離、高度、側面）
- 畫面上每個東西的意思（骨架顏色、角度標籤、大字儀表板、提示顏色）
- 錄製與重播怎麼用
- 常見問題（AI 載入很慢、沒有偵測到人、iPhone 注意事項、`?sw=0` 等網址參數）
- 隱私：影像只在自己的裝置上處理，不會上傳

## 五、登入與帳號（目前不做，先記錄需求）

目前網站放在 GitHub Pages 上，只有網頁檔案、沒有伺服器，所以**沒有登入功能**。所有分析都在使用者自己的裝置上完成，影像不上傳。

如果之後要「登入後保存自己的運動紀錄」，需要：
1. 後端服務：存帳號與紀錄，例如 Firebase、Supabase 或學校的伺服器。
2. 隱私說明與同意：上傳的是骨架座標，不是影像；要讓使用者知道、可以刪除。
3. 頁面：登入、我的紀錄（列表）、單次紀錄（就是現在的重播分析頁）。

現在的「錄製 → 下載 JSON → 重播分析」已經是同一套流程的單機版。之後接上後端時，主要是把「下載／選檔案」換成「上傳／從清單選」，分析畫面可以沿用。
