# YOLO：校正和自己訓練（11/21）

網站可以選 MediaPipe 或 YOLO（首頁「進階設定 → AI 模型」）。官方的 YOLO 有兩個問題要靠**組員的真人影片**解決：

1. **角度和 MediaPipe 不一樣**：網站的門檻（例如深蹲蹲到 90° 以下算到位）是照 MediaPipe 訂的。11/21 用伏地挺身示範影片比：YOLO 的手肘在彎到底時比 MediaPipe 大 10° 以上。同一個門檻用在 YOLO，「到位」會變難。→ **校正**（第 5 步）
2. **沒有腳跟、腳尖**：深蹲的「腳跟離地」、弓箭步的「前膝超過腳尖」用 YOLO 時不判斷。→ **自己訓練一個有腳的 YOLO**（第 6 步）

兩步都是「工具做好了，等影片」。影片、錄製檔是組員的真人錄影：**只放在自己的電腦，不要放進 GitHub**（repo 是公開的）。

## 拍影片

- 側面拍、整個人在畫面裡、手機放穩（和網站建議的拍法一樣）。
- 每個動作（深蹲、伏地挺身、弓箭步、棒式）每人 10 下以上，至少 2 位；故意做錯的也拍（例如墊腳的深蹲），校正和訓練都用得到。
- 一般的 MP4 就可以。

## 第 5 步：校正（兩個模型差幾度、門檻要改成多少）

1. 打開網站的「模型對照」（重播分析底下，`compare.html`），選影片、動作，模型 A 選 **MediaPipe full**、模型 B 選 **YOLO26n**（或 26s），按「開始對照」。
2. 頁面上就看得到：兩個模型各數到幾下、每一下最低幾度、每個關節平均差幾度。
3. 按「下載 A 的錄製檔」「下載 B 的錄製檔」，再在專案資料夾跑：

   ```
   node tools/calibrate-models.mjs A的錄製檔.json B的錄製檔.json
   ```

   會列出：B 比 A 在每 15° 一段各多幾度、**每個計次門檻換成 B 要改成幾度**（資料不夠的那一段寫「先不改」）、看不看得到的差別（YOLO 對被擋住的那一側也很有把握）。
4. 好幾段影片的建議都差不多，大家看過，再把門檻改進網站（分模型的門檻，到時候另外開 PR）。

## 第 6 步：自己訓練有腳跟、腳尖的 YOLO

想法：MediaPipe 有腳跟、腳尖，用它幫影片的每一格「標答案」，拿來訓練 YOLO 多學 4 個點（21 點）。

要一台裝 Python 的電腦（Linux 或 Mac；有 NVIDIA 顯示卡會快很多）：

```
python3 -m venv venv
venv/bin/pip install ultralytics==8.4.215 litert-torch==0.10.0
```

1. 每段影片先在「模型對照」用 **MediaPipe full** 算一次（模型 B 隨便選），下載 **A 的錄製檔**。
2. 影片＋錄製檔 → 訓練資料（每段影片跑一次，`--out` 用同一個資料夾）：

   ```
   venv/bin/python tools/yolo-dataset.py 影片.mp4 A的錄製檔.json --out datasets/feet
   ```

   每 2 格取 1 格，每一格存兩張圖：整個畫面，和網站「先框出人」時看到的那一塊（人放大到大約 2 倍；網站大部分的格子是這樣看的，只用整個畫面訓練的話，放進網站後只有七成的格子找到人）。影片最後 20% 當驗證資料。看得到的點少於 8 個的格子不用。也會寫進每個點的容許範圍（官方 17 點的值，腳跟、腳尖用腳踝的），訓練時的扣分和算準確度才和官方一樣。
   - **留一兩位組員的影片完全不拿來訓練**：每段影片最後 20% 的驗證資料是同一個人、同一個場景，準確度會偏高；真的準不準，要用沒訓練過的人的影片在「模型對照」比（和 11/2 的 AI 模型一樣：同一個受測者不能同時在訓練和測試兩邊）。
3. 訓練（從官方的 YOLO26n-pose 開始，只要再學 4 個點）：

   ```
   venv/bin/python tools/yolo-train.py datasets/feet/data.yaml --epochs 50
   ```

   只有 CPU 時先 `--epochs 1` 試流程。跑完會印出驗證資料的準確度（pose mAP50、mAP50-95，越接近 1 越好）和轉好的網站用檔案（`.tflite`）、sha256。
   - 工具會先把官方 17 個點的參數搬進新模型：點數從 17 改成 21 時，Ultralytics 會把模型找點的那一段整段重來，連原本 17 個點學好的也丟掉（11/21 試過：沒搬的話，膝蓋以下的點全擠到上半身）。搬了之後一開始 17 個點和官方一模一樣；腳跟、腳尖一開始放在腳踝的位置（就在旁邊），只要學差一點點的地方（從隨機開始的話會落在人的中間，試過 30 輪還在上半身）。
4. 放進網站（另外開 PR）：檔案放 `models/yolo/`；`js/ai/models.js` 加一筆（`feet: true`、`kpts: 21`）；`js/config.js` 的 `YOLO_FILES`、`sw.js` 的 `AI_SHA256`、`models/yolo/README.md` 各加一行；首頁的選單：`js/ai/model-choice.js` 的 `MODEL_CHOICES`、`js/pages/main.js` 的 `MODEL_TEXT` 和 `MODEL_GROUPS`。網站已經認得 21 點的 YOLO（`js/ai/keypoints.js`、`js/ai/yolo-core.js`）；模型對照頁的選單照 `js/ai/models.js` 自動列出來。
5. 用「模型對照」比自己訓練的和 MediaPipe：腳跟、腳尖的位置差多少，「腳跟離地」判斷得一不一樣。

### 11/21 用示範影片試過一次（只在開發環境）

用 Ultralytics 的伏地挺身示範影片（2 秒，重複 4 次）把第 5、6 步從頭到尾跑過：

- 校正（MediaPipe full 對官方 YOLO26n）：手肘彎的時候（45～90°）YOLO 大 20～28°，伸直時差不到 4°；「到位」的 95° 建議改成 108°。這只是一段示範影片的數字，門檻要等組員的影片。
- 訓練：120 格 → 訓練 192 張、驗證 48 張；這台 4 核心的電腦只用 CPU 訓練 30 輪約 7 分鐘，驗證資料的準確度 mAP50-95 0.92。
- 放進網站的複本，在模型對照頁和 MediaPipe full 比：每一格都找到人、一樣數到 3 下，每一下最低的手肘差 2°，腳跟、腳尖差 4～8 像素（640×360 的畫面）。
- 過程中修好兩個問題（工具已經改好）：17 個點沒有搬過去的話，膝蓋以下的點全擠到上半身；只用整個畫面訓練的話，網站「先框出人」之後只有 70% 的格子找到人。
- 訓練和測試是同一段影片：只證明流程走得通、網站讀得懂 21 個點；換一個人準不準，要用組員的影片照上面的方法比。

注意：答案是 MediaPipe 標的，MediaPipe 錯的地方 YOLO 也會學到；重要的影片要人工看過（Ultralytics 的標記工具或 CVAT 都能改）。授權：從 YOLO26 訓練出來的模型一樣是 AGPL-3.0（`models/yolo/README.md`）。
