# 程式架構

這份文件說明整個網站的程式怎麼分工：每個資料夾負責什麼、鏡頭的一格畫面會經過哪些程式，以及怎麼測試。第一次看程式碼，建議先讀這份。

## 一、設計原則

1. **影像不離開裝置**：AI 在使用者自己的手機或電腦上執行，鏡頭影像不會上傳。錄製的只有關鍵點座標，而且只會存成使用者自己下載的檔案。雲端（Firebase）只在使用者打開「雲端同步」時存運動總結的數字（`js/cloud/`）。
2. **不需要安裝、不需要編譯**：純 HTML、CSS、JavaScript（ES 模組），直接放在 GitHub Pages 上就能用。沒有打包工具，原始碼就是實際執行的程式。
3. **一個檔案只做一件事**：例如 `smooth.js` 只負責平滑、`angles.js` 只負責算角度。要改某個功能時，只需要看一個檔案。
4. **畫面與計算分開**：計算的程式（`skeleton/`、`analysis/`、`data/`）不碰畫面，可以直接拿來測試，鏡頭頁和重播頁也共用同一份。
5. **原始資料永遠保留**：平滑、擋鬼點都只影響畫面上畫的東西；錄製檔同時存原始資料和處理後的資料，之後換方法時不用重錄。
6. **註解寫原因**：每個檔案開頭說明它的用途，數字門檻旁邊寫「為什麼是這個數字」，以及是用什麼測試、模擬決定的。

## 二、資料夾

```
claude-workspace/
├── index.html          首頁＋鏡頭畫面
├── replay.html         錄製資料重播分析
├── report.html         實測報表（重播分析底下：一次讀很多個實測檔，比對每一組）
├── protractor.html     照片量角器（使用說明「驗證實驗 A」的另一種量法：在照片上拖三個點量角度，和 AI 比）
├── help.html           使用說明
├── results.html        研究成果（使用說明底下：目前量到的數字整理成一頁，報告時打開；10/28）
├── sw.js               離線功能（Service Worker；瀏覽器規定要放在網站最外層）
├── manifest.webmanifest  加到手機主畫面（10/29）：名稱、圖示、從主畫面打開沒有網址列、長按圖示的四個動作捷徑
├── icons/              主畫面圖示（192、512、Android 裁切用的 maskable 512、iPhone 的 180）
├── firestore.rules     雲端資料庫的安全規則（貼到 Firebase 主控台；docs/firebase-setup.md）
├── firebase.json       Firebase 本機模擬器的設定（開發、測試用）
├── css/
│   ├── style.css       全站共用的樣式（三頁共用的導覽列、首頁、鏡頭畫面、使用說明）
│   └── replay.css      重播分析頁專用的樣式
├── js/
│   ├── config.js       全站設定：MediaPipe 版本、模型位置、網址參數
│   ├── pages/          每一頁的主程式：把下面的模組組合起來、處理按鈕
│   ├── ai/             AI 模型：載入 MediaPipe、在背景執行緒偵測骨架
│   ├── skeleton/       骨架處理：平滑、擋鬼點、往前預測、3D 座標穩定化
│   ├── analysis/       動作判斷：關節角度、拍攝方向、入鏡提示、深蹲次數
│   ├── ui/             畫面元件：骨架、標籤、大字儀表板、數據表、曲線圖
│   ├── platform/       裝置功能：鏡頭、螢幕保持亮著、離線、GPU、裝置支援檢查
│   ├── cloud/          雲端同步（Firebase）：網站只透過這裡用雲端，之後換成自己的伺服器只改這裡
│   └── data/           錄製與重播：匯出 CSV／JSON、讀檔重算、合成示範資料
├── tools/              命令列工具（開發用，11/2 起）：dataset.mjs 實測檔 → AI 模型的資料（CSV）、split.mjs 訓練和測試照受測者分、
│                       train.mjs 訓練 AI 模型（Random Forest）並和規則、DTW 比（--test 一種分法、--cv 交叉驗證、--module 存成網站用的模型）、
│                       evaluate.mjs 三種判斷法各猜對幾下、train-activity.mjs 訓練「AI 自動辨識動作」的模型（11/8）
├── tests/              自動測試（node --test tests/）
├── docs/               文件（這份、資料格式、設計規劃、日後改進）
└── .github/workflows/  自動化：發布網站、每次推送時跑測試
```

## 三、一格畫面的流程

鏡頭每一格畫面，從拍到畫出來會經過這些程式（`pages/main.js` 負責串起來）：

```mermaid
flowchart LR
    CAM["鏡頭<br>platform/camera.js"] --> AI["AI 偵測 33 個點<br>ai/pose.js<br>（背景執行緒 ai/pose-worker.js）"]
    AI --> PIPE["骨架處理<br>skeleton/pipeline.js"]
    subgraph PIPE_IN [" "]
        direction TB
        S1["平滑<br>smooth.js"] --> S2["擋鬼點<br>ghost.js"] --> S3["角度<br>analysis/angles.js"] --> S4["拍攝方向<br>analysis/view.js"]
    end
    PIPE --- PIPE_IN
    PIPE --> PRED["往前預測<br>skeleton/predict.js"] --> DRAW["畫骨架、標籤<br>ui/draw.js、ui/labels.js"]
    PIPE --> HUD["大字儀表板、入鏡提示、次數、錯誤<br>ui/hud.js、analysis/framing.js、analysis/workouts.js、analysis/form.js"]
    AI --> REC["錄製（原始＋處理後）<br>data/recorder.js"]
    AI --> WORLD["3D 座標穩定化<br>skeleton/world.js"] --> REC
```

重點：

- **角度、深蹲判斷、錄製都用沒有預測的數字**，預測只影響畫出來的位置。
- **錄製檔保留 AI 的原始輸出**，處理後的資料另外存一份（欄位在後面），格式見 [data-format.md](data-format.md)。
- **重播分析頁**（`data/replay-core.js`）把錄製檔一格一格丟進**同一個** `skeleton/pipeline.js`，結果和當下鏡頭畫面完全相同，所以可以用錄影檢查判斷得對不對。

## 四、執行緒

| 執行緒 | 做什麼 | 為什麼 |
|---|---|---|
| 主畫面 | 按鈕、畫骨架、平滑與判斷（每格約 1 毫秒） | 要碰畫面的工作只能在這裡 |
| AI 背景執行緒（`ai/pose-worker.js`） | 跑 MediaPipe（每格 20～60 毫秒） | 最重的工作移出去，按鈕、動畫不會卡；不支援的瀏覽器自動改在主畫面跑 |
| 重播背景執行緒（`data/replay-worker.js`） | 讀檔（選的檔案直接交給它讀）、重算整段錄影 | 5 分鐘的檔案在手機上要算好幾秒；20 分鐘的檔案超過 100 MB，在主畫面讀會卡住、記憶體多用一份 |
| Service Worker（`sw.js`） | 存 AI 檔案，第二次打開不用下載、沒網路也能用 | 18 MB 的 AI 檔案每次重新下載太慢 |

## 七、發布

推送到 `main` 分支後，`.github/workflows/deploy.yml` 會自動發布到 GitHub Pages（約 1 分鐘）。發布時會在每個 JS、CSS 檔名後面加上版本號（例如 `main.js?v=1a2b3c4d`），手機才不會用到「新舊混在一起」的檔案。

## 八、外部套件和安全更新

| 套件 | 用在哪 | 固定的版本 | 11/10 最新 | 安全問題 | 決定 |

下次怎麼檢查：

1. `npm view @mediapipe/tasks-vision version`、`npm view firebase version`、`npm view firebase-tools version` 看最新版。
2. 在暫存資料夾寫一個只有這幾個套件、版本和專案一樣的 `package.json`，`npm install --package-lock-only --ignore-scripts` 之後 `npm audit`（只算出套件清單，不會下載、執行套件）。
3. 報出來的問題要看是在瀏覽器版還是 Node.js 版：網站只用瀏覽器版。

4. 新版先比過再換（工具在暫存區的 `audit1110/tools/`，也備份在 `test-tools` 分支）：MediaPipe 用 `mp_compare.mjs` 拿同一批畫面比新舊版本的骨架座標、角度、速度；Firebase 把網站複本的 `FIREBASE_VERSION` 改成新版，用新版的 npm 套件在本機模擬器跑雲端同步檢查（`fbcheck/cloud.py`）和 `ai_sdk_check.mjs`（AI 教練用真的 Firebase AI 程式，Google 的伺服器換成假的）。

換 MediaPipe 版本見上面第六節；換 Firebase 版本改 `js/cloud/config.js` 的 `FIREBASE_VERSION`，再跑 `npm run test:rules` 和 `npm run test:live`；換 firebase-tools 改 `.github/workflows/test.yml`（兩個地方）和 `CLAUDE.md`。
