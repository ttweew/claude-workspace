# 日後改進與規劃

這份文件記錄「已經知道、但還沒做」的事情，避免只存在對話裡而遺失。
每完成一項就把狀態改成「完成」並寫上 PR 編號。

## 一、程式改進清單

來源：程式碼檢視（含請其他 AI 挑毛病後，逐條查證過、確定成立的項目）。

| # | 項目 | 為什麼要做 | 狀態 |
|---|---|---|---|
| 1 | 判斷拍攝方向（正面／側面），正面拍時提示側身 | 深蹲、伏地挺身的膝、髖角度要從側面拍才準；正面拍時大腿往鏡頭方向彎，畫面上的角度會比實際大很多 | 未做 |
| 2 | 線段在畫面上太短時不顯示角度 | 例如大腿正對鏡頭時只剩幾個像素長，1～2 個像素的抖動就會讓角度跳幾十度 | 未做 |
| 3 | 判斷關節往哪一邊彎（偵測膝蓋過度伸直） | 目前的角度只有 0～180°，膝蓋往前彎 170° 和往後反折 190° 都顯示 170° | 未做 |
| 4 | 平滑程式遇到壞掉的數字（NaN）時沿用上一個值 | 現在一格壞掉的數字會讓那個點之後永遠是 NaN，直到關鏡頭 | 未做 |
| 5 | 輸入的點數改變時，平滑程式自動重新建立 | 之後換模型或加入自訂點時，點數不同會讓平滑程式出錯 | 未做 |
| 6 | 模型永久保存在手機裡（Service Worker） | 第二次打開時不用重新下載，沒有網路也能用 | 需要時再做 |
| 7 | 下載卡住（沒有錯誤也沒有資料）時，逾時自動重試 | 現在網路斷斷續續時，進度條可能一直停在同一個數字 | 未做 |
| 8 | 關鍵點的設定改成一張表（是否為主要關節、算出來的點） | 之後加動作模板、自訂點時比較好改 | 做動作模板時再做 |

## 二、要等真人、真手機才能確認的事

| 項目 | 需要什麼 |
|---|---|
| 鬼點在真實手機上是否改善 | 組員用手機實際測試 |
| `?model=full` 在手機上的速度（FPS） | 各組員手機各測一次，記下 FPS |
| 鏡頭清單有沒有出現超廣角（0.6×）鏡頭 | 有超廣角鏡頭的手機打開鏡頭清單看看 |
| iPhone 是否正常 | 用 iPhone 測試 |
| 判斷準不準（驗證實驗） | 真人錄影，見 [data-format.md](data-format.md) 的「驗證實驗建議」 |

## 三、接下來的階段

1. **動作判斷的地基**：上面清單第 1～3 項
2. **重播驗證工具**：把錄製檔重新跑一遍、畫出角度曲線，錄影一到就能量準確度
3. **深蹲**：次數計算、是否蹲到深度，先做成隱藏的實驗功能
4. **其他動作**：伏地挺身、棒式、弓箭步（順序待討論）
5. **動作模板與錯誤提示**：每個動作的標準與常見錯誤
