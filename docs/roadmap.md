## 四、深蹲實驗功能（`?lab=squat`）

一般使用者看不到；網址加上 `?lab=squat` 才會出現（例如 `https://ttweew.github.io/claude-workspace/?lab=squat`），重播分析頁也一樣（`replay.html?lab=squat`）。

**怎麼算一下**：先站直（膝蓋 ≥ 160°）→ 往下蹲到膝蓋 ≤ 140° → 再站直。兩個門檻不同，角度在門檻附近抖動時才不會多算；不到 0.5 秒的不算；蹲到一半看不到人超過 1.5 秒，那一下作廢。

**深度判斷**（看每一下最低的膝蓋角度）：≤ 90° 蹲到位、90～110° 再低一點、> 110° 太淺。

**只在側面、斜側面拍時計算**，正面拍會提示「請側身對著鏡頭」。

**畫面上**：大字儀表板多一格「深蹲」次數；每完成一下，上方短暫顯示「第 3 下 · 85° 蹲到位」（綠：蹲到位、黃：再低一點、紅：太淺）。

用合成資料測試（14 項全部通過；另外把 MediaPipe 換成播放合成深蹲的假模組，從鏡頭畫面端到端測試，5 下全部正確顯示）：

| 情境 | 結果 |
|---|---|
| 拍攝角度 0°、8°、20°、28°，面向左右都測 | 5 下全對；側面時最低膝蓋角度誤差 ≤ 3.6°，斜 28° 時 ≤ 7.3° |
| 正面拍 | 0 下，99% 的時間有提示側身 |
| 雜訊加倍（3 像素） | 5 下全對 |
| 只是小幅度晃動（膝蓋 145～152°） | 0 下（不會誤算） |
| 很快（每下 1.2 秒）、很慢（每下 7.5 秒、底部停 2 秒） | 都算對 |
| 蹲到一半看不到人 2 秒 / 0.5 秒 | 那一下作廢 / 照算 |
| 一開始就蹲著 | 第一下不算（要先站直） |

**要和老師、組員討論的**：
- 深度門檻：90° 是很多健身 App 的常用門檻；大腿和地面平行時膝蓋約 60～70°。要以哪個為「蹲到位」？
- 要不要加其他判斷：例如上半身前傾太多（髖部角度）、膝蓋內夾（要正面拍才看得到，和側面拍衝突）
- 真人錄影驗證：用重播分析頁（`replay.html?lab=squat`）檢查每一下有沒有算對

## 五、第一次真實錄影（10/5）

組員找朋友錄了兩段（Android 手機、三星瀏覽器、GPU、手機直拿 480×640、後鏡頭）：49 秒（站著、手部動作、蹲坐在地上、側身走動與類似弓箭步的動作）和 13 秒（站著，再走近鏡頭、走出畫面）。兩段都是正面為主，不是驗證實驗 D、H 的錄法（下面「第 3 段」是同一天稍晚錄的）。

| 項目 | 結果 |
|---|---|
| 速度 | 每秒約 30 格，間隔穩定（9 成在 39～42 毫秒以內） |
| 檔案 | JSON 和 CSV 讀進重播分析，結果完全相同；平滑後的點、處理過的公尺座標都有存到 |
| 平滑 | 角度每格的跳動：原始 0.9～1.2° → 平滑後 0.45～0.8°（膝、髖、肘） |
| 公尺座標的骨頭長度 | 兩段錄影一致：大腿 35～37 公分、小腿 39～42 公分；處理過的版本變動稍小（例如小腿 ±1.5 → ±0.8 公分）。沒有捲尺量的長度，還不能說準不準 |
| 發現的問題 | 改進清單第 10～13 項 |

**第 3 段（同一天 14:45，97 秒）**：人站得比較近（約佔畫面高度 6 成），手機高度也比較接近腰部（站直時每公分的像素：軀幹 2.6、大腿 2.25、小腿 1.85）。內容：正面站、轉身成側面、側面深蹲蹲到底（膝約 28°）後轉身面向手機、正面深蹲、側面深蹲（膝約 24°）。

- 拍攝方向判斷：正面、側面、斜側面都和動作相符
- 公尺座標的骨頭長度和前兩段一致：大腿 36.5～36.8 公分、小腿 38.8～40.3 公分（第 1 段的人站得比較遠、手機比較高，估計值仍在 1～2 公分內）
- 找到改進清單第 14、15 項：轉身時骨架消失 0.7 秒、蹲完轉身那一下沒算到。修正後兩下側面深蹲都算到（最低膝蓋 28°、24°，都是「蹲到位」）
- 入鏡提示（改進清單第 12 項，PR #57）：三段錄影重跑，「請再往後退」只剩腳真的出了畫面的那一段（第 3 段 18～25 秒）；蹲低、坐下時改成「看不到腳，可能被擋住了」；蹲到底時的「離太遠了」不再出現

**手機放得比較高**：用公尺座標當尺，站直時每公分在畫面上佔的像素：軀幹、手臂約 2.0，大腿 1.2，小腿 0.85。越下面的部位縮得越多，是鏡頭從高處往下拍的現象。使用說明寫「手機約在腰部高度」，但實際使用時不一定照做，所以程式不能假設手機的高度。

## 六、筆電與 iPhone 錄影（10/6）

10/6 另外錄了兩段：筆電那段和 10/5 的 Android 錄影是同一個人；iPhone 那段還沒確認是不是同一位。

| | Windows 筆電（Chrome） | iPhone（Chrome，iOS 26） |
|---|---|---|
| 運算、速度 | GPU，每秒 30 格 | GPU，每秒 30 格（9 成的間隔在 34 毫秒以內，比 Android 更穩） |
| 長度 | 3 分 22 秒 | 3 分 56 秒 |
| 內容 | 正面站立、手部動作、正面深蹲；側面深蹲 5 下 | 正面站立、正面深蹲；側面站立與淺蹲 2 下；斜側面、側面蹲低；正面蹲坐約 30 秒 |
| 深蹲次數 | 側面 5 下全部算到（最低膝蓋 31°、34°、57°、65°、97°） | 側面 2 下淺蹲算到；正面的蹲不計（正確） |
| 公尺座標的骨頭長度 | 大腿 37.3～37.7、小腿 37.2～38.0 公分 | 大腿 38.2～38.6、小腿 39.3～40.3 公分 |
| 發現的問題 | 人站得太近：腳碰到畫面下緣、頭碰到上緣（錄影任務卡已加提醒） | 改進清單第 16 項：側面蹲低時骨架藏了 10 秒 |

- 同一個人在 Android 手機和筆電上算出的大腿、小腿長度差距約 2 公分以內（iPhone 那段也在同一範圍）。還沒有捲尺量的長度，只能說「穩定」，還不能說「準」
- 筆電那段側面 5 下，算出的深度是 2 下很深（31°、34°）、2 下中等（57°、65°）、1 下淺（97°）；不知道每一下原本想蹲多深，所以還不能對照。錄影任務卡已加上「每一下之前喊出深、半、淺」
